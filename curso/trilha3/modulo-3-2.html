👥 Time de três papéis

Um modelo forte planeja, um médio faz e um leve confere. Cada papel usa só o modelo de que precisa, e a cota rende. É a receita R2 do kit, com prova no CHANGELOG.

1

Conheça o planejador, o executor e o revisor

A receita R2 divide uma tarefa em três papéis. O planejador pensa e escreve o plano. O executor faz. O revisor confere se ficou pronto de verdade.

É o roteamento do módulo 3.1 aplicado numa tarefa só: pensar usa modelo forte, fazer usa médio, conferir usa leve. Ninguém paga topo para tarefa de conferência.

🆕 Novo aqui? Subagente e papel

  • Subagente — um ajudante que o Claude Code chama durante a conversa. Ele recebe uma parte do trabalho, faz com o modelo e as ferramentas dele e devolve o resultado. É um recurso oficial do Claude Code.
  • Papel — o "cargo" do subagente: o que ele faz, que modelo usa e o que pode tocar. No kit, cada papel é um arquivo em .claude/agents/.
PapelArquivoModeloFaz
planejadorplanejador.mdopusplano curto com critério de pronto comando → saída esperada
executorexecutor.mdsonnetexecuta o plano e mostra a prova
revisorrevisor.mdhaikuroda os critérios; responde APROVADO ou o que falta

O que olhar na tabela: a coluna Modelo desce de nível da primeira para a última linha (topo, executor, menor no ROTEAMENTO.md). A tabela é a mesma da receita R2.

Como ler o desenho: a tarefa anda da esquerda para a direita. Só o executor (azul) mexe em arquivos. O revisor fecha com APROVADO; se algo falhar, a linha vermelha tracejada devolve a lista do que corrigir ao executor.

2

Leia os arquivos dos papéis

Cada papel é um arquivo de texto curto. Em cima vem uma ficha entre linhas ---; embaixo, as instruções em português. Este é o .claude/agents/planejador.md, inteiro:

📄 .claude/agents/planejador.md (do kit)
---
name: planejador
description: Planeja uma tarefa antes de executar. Use no início do time de três papéis (runtime/receitas/R2). Não edita arquivos.
model: opus
tools: Read, Grep, Glob
---
Você é o planejador do time. Leia a tarefa e o que for preciso do projeto, sem alterar nada.

Devolva somente:
1. Plano em no máximo 5 passos.
2. Critérios de pronto, um por linha, no formato `comando → saída esperada`, que só passam se o trabalho for feito de verdade.
3. Riscos pela runtime/POLITICA.md (ações que exigem pedir antes).
Repare: a lista tools não tem Write nem Edit. O planejador não consegue alterar arquivo nem que queira.

🆕 Novo aqui? Frontmatter e ferramentas

  • Frontmatter — a ficha no topo do arquivo, entre as duas linhas ---. O Claude Code lê ali o nome, a descrição, o modelo e as ferramentas do papel.
  • description — diz ao Claude quando chamar esse papel. Por isso cita a receita R2.
  • tools — as ferramentas liberadas: Read (ler), Grep/Glob (procurar), Write/Edit (criar e alterar), Bash (rodar comandos).
Papeltools: no arquivoInstrução que segura o papel
planejadorRead, Grep, Glob"sem alterar nada"
executorRead, Write, Edit, Bash, Grep, Glob"não envie, não apague, não gaste crédito; se o plano pedir isso, pare e devolva a pergunta"
revisorRead, Bash, Grep, Glob"Não altere arquivos." Termina com APROVADO ou FALTA:

O que olhar na tabela: o revisor tem Bash para rodar os critérios, mas não tem Write nem Edit. Ele confere sem poder "consertar por baixo" o que achou.

✓ Papel bem escrito

  • ✓ Ferramentas mínimas para o trabalho
  • ✓ Saída com formato fixo (plano, OK/FALHA)
  • ✓ Cita a POLITICA.md
  • ✓ Cabe numa tela

✗ Papel mal escrito

  • ✗ Todas as ferramentas "por via das dúvidas"
  • ✗ Revisor que pode editar o que revisa
  • ✗ Resposta livre, sem veredito claro
  • ✗ Modelo topo em tudo

3

Rode o time pela tela do Claude

O jeito mais simples é conversar. Você abre o Claude Code na pasta do kit e pede o time pelo nome dos papéis. O Claude chama cada subagente na ordem.

A tarefa de teste é de propósito boba: criar um arquivo com uma frase. Assim você vê o time funcionar sem se preocupar com o conteúdo.

🎯 Objetivo: ver os três papéis trabalhando numa tarefa pequena

Abra claude na pasta do kit e cole (prompt da receita R2):

Use o time: o planejador planeja, o executor faz e o revisor confere. Tarefa: crie saudacao.txt com a frase "Olá, comunidade INEMA".

Quando terminar, confira o arquivo no terminal:

cat saudacao.txt

Resultado esperado (pela receita):

cat saudacao.txt mostra a frase e a resposta termina com APROVADO.
Como verificar: o arquivo tem a frase "Olá, comunidade INEMA" e a última palavra do revisor é APROVADO. Se vier FALTA:, leia a lista: é o que o executor deixou de fazer.
1

Planejador devolve o plano

Até 5 passos, os critérios de pronto no formato comando → saída esperada e os riscos pela política.

2

Executor faz e mostra a prova

Cria o arquivo, roda o comando de prova de cada passo e lista o que criou ou alterou.

3

Revisor dá o veredito

Uma linha por critério, OK ou FALHA com a saída, e no fim APROVADO ou FALTA:.

💡 O critério nasce antes do trabalho

O planejador escreve o critério de pronto antes de o executor começar. Assim o revisor confere contra o que foi combinado, e não contra o que o executor diz que fez. É a mesma ideia de "prova" das receitas.

4

Rode o time sem abrir a tela

O mesmo pedido cabe numa linha de terminal. Você não conversa: manda a tarefa, espera e lê a resposta final. Serve para repetir o time toda semana com a mesma frase.

🆕 Novo aqui? O -p do Claude

claude -p "pedido" roda o pedido uma vez e imprime a resposta, sem abrir a tela de conversa. O "p" vem de print (imprimir). É o que permite chamar o Claude de um script ou de outro agente.

🎯 Objetivo: rodar o time inteiro com um único comando

No terminal, dentro da pasta do kit:

claude -p "Use o time (planejador, executor, revisor). Tarefa: crie saudacao.txt com a frase 'Olá, comunidade INEMA'. Termine com a resposta do revisor."

Resultado provado no CHANGELOG 0.1.0:

modelos opus + sonnet + haiku usados; revisor APROVADO; saudacao.txt correto
Custo da R2 em cota: equivalente a ~US$ 0,73 de API (não é cobrança na assinatura).
Como verificar: a resposta termina com a do revisor (APROVADO) e cat saudacao.txt mostra a frase.

Como ler o desenho: à esquerda, os três papéis ficam à vista na conversa. À direita, eles rodam dentro da caixa roxa do claude -p e você só vê o que sai. Mesmo time, mesma cota; muda quanto você acompanha.

⚠️ -p não é o mesmo que segundo plano

O claude -p segura o terminal até acabar. Soltar o time para rodar enquanto você faz outra coisa é o claude --bg, do módulo 3.3. E os dois não se misturam: o CHANGELOG 0.2.0 registra que --bg não aceita -p.

Use o time no seu trabalho

Para usar de verdade, troque só a tarefa. A receita R2 traz dois exemplos, um para cada personagem do curso. O que muda de um para o outro é o que o revisor confere.

🧾

Sônia — totais do ERP

Exemplo da R2: "planeje e monte um resumo do CSV exportado do ERP em export/; o revisor confere os totais".

Para treinar, use o runtime/exemplos/erp-vendas.csv. O total dele é R$ 856,00, conta que você pode fazer à mão.

🩺

Clara — horários livres

Exemplo da R2: "liste os horários livres da semana na agenda.csv; o revisor confere se nenhum horário ocupado apareceu".

Para treinar, use o runtime/exemplos/agenda.csv, com a Dra. Ana e o Dr. Bruno.

🎯 Objetivo: o time da Sônia, com revisor conferindo o total

Abra claude na pasta do kit e cole:

Use o time: o planejador planeja, o executor faz e o revisor confere. Tarefa: monte resumo-vendas.md com o total por cliente do runtime/exemplos/erp-vendas.csv e o total geral. O revisor confere os totais somando direto do CSV.

Para a Clara, troque a tarefa:

Use o time: o planejador planeja, o executor faz e o revisor confere. Tarefa: liste em horarios-livres.md os horários livres da runtime/exemplos/agenda.csv. O revisor confere se nenhum horário ocupado apareceu.
Como verificar: o revisor termina com APROVADO. Na Sônia, o total geral tem de dar R$ 856,00 (10×18,50 + 25×5,20 + 40×5,20 + 6×18,50 + 12×18,50). Na Clara, compare com as linhas livre do CSV.

💡 Diga ao revisor o que conferir

"O revisor confere" sozinho é vago. "O revisor confere os totais somando direto do CSV" vira critério. Quanto mais concreto o que ele confere, mais o APROVADO vale.

⚠️ O executor para antes de enviar ou apagar

Pela política da R2, o executor altera arquivos do projeto (N3) e nada além. Se a tarefa da Clara virar "e mande a lista aos pacientes", ele para e devolve a pergunta: enviar tem teto N2 na POLITICA.md.

Troque modelos e crie papéis

Os papéis são seus. A seção "Ajustes" da R2 mostra os dois jeitos de mexer: trocar o modelo de um papel e criar um papel novo.

Para trocar o modelo, edite a linha model: do arquivo do papel. Os valores aceitos são haiku, sonnet, opus ou inherit, que usa o mesmo modelo da sua sessão.

📄 Frontmatter do .claude/agents/revisor.md (do kit)
---
name: revisor
description: Confere o trabalho do executor rodando os critérios de pronto do plano. Use no fim do time de três papéis (runtime/receitas/R2). Não edita arquivos.
model: haiku
tools: Read, Bash, Grep, Glob
---
Onde mexer: se o revisor deixar passar erro nas contas da Sônia, troque model: haiku por model: sonnet. É a regra "suba só se errar" do módulo 3.1.
Valor de model:Nível no ROTEAMENTO.mdQuando usar no time
haikumenorconferir critérios simples
sonnetexecutor (ou menor)fazer o trabalho; revisor mais atento
opustopo (ou executor, com esforço baixo)planejar
inherito da sua sessãoquando você já escolheu o modelo ao abrir o claude

O que olhar na tabela: a segunda coluna liga cada valor à tabela do módulo 3.1. Note que sonnet aparece em dois níveis lá: o roteamento é um guia, não uma prisão.

Para criar um papel, a R2 manda copiar um arquivo de .claude/agents/ e mudar nome, descrição e instruções. Dá para pedir ao próprio Claude, que mostra a mudança antes de salvar:

🎯 Objetivo: um quarto papel, a partir do revisor

Abra claude na pasta do kit e cole:

Copie .claude/agents/revisor.md para .claude/agents/conferente-agenda.md. Mude name, description e instruções: ele confere se uma lista de horários livres bate com as linhas livre da runtime/exemplos/agenda.csv. Mantenha as mesmas tools e model: haiku. Mostre o arquivo antes de salvar.
Como verificar: o arquivo novo existe em .claude/agents/, o frontmatter tem name: conferente-agenda e a lista tools continua sem Write e Edit.

Teste rápido (opcional): por que o revisor do kit não tem Write nem Edit?
