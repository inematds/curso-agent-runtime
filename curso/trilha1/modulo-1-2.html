1

Confira o que você precisa ter

A lista é curta. O README do kit pede três coisas: Node 18 ou mais novo, o Claude Code e/ou o Codex logados pela assinatura, e um computador com Linux ou Mac. No Windows, use o WSL.

Basta um dos dois agentes para começar. Com os dois, você aproveita todas as receitas, inclusive a R1, em que o Claude pede ajuda ao Codex.

🆕 Novo aqui? Quatro termos deste módulo

  • Terminal — a janela de texto onde você digita comandos e aperta Enter. No Mac, o app se chama Terminal; no Linux, também.
  • Node — o programa que roda os scripts do kit (os arquivos .mjs). Também traz o npm, que instala ferramentas.
  • WSL — o Linux que roda dentro do Windows. É por ele que quem usa Windows segue este curso.
  • Login pela assinatura — entrar no Claude Code ou no Codex com a mesma conta do plano mensal. Nada de chave de API.

✓ Você precisa

  • ✓ Node 18 ou mais novo
  • ✓ Claude Code ou Codex (ou os dois), logados
  • ✓ Linux, Mac ou Windows com WSL
  • ✓ Uma pasta onde o kit vai morar

✗ Você não precisa

  • ✗ Chave de API paga
  • ✗ Servidor, nuvem ou painel web
  • ✗ Saber programar
  • ✗ Ollama (é opcional: modelos locais grátis)

2

Clone o kit na sua máquina

O kit mora no GitHub. Um comando copia tudo para uma pasta nova no seu computador. O nome meu-projeto é sugestão do README: troque pelo nome do seu trabalho, se quiser.

A pasta clonada vira o seu projeto. As regras, as pontes e as receitas já chegam no lugar certo. Você não instala nada além disso.

🆕 Novo aqui? Git, repositório e clone

Git é o programa que guarda o histórico de mudanças de uma pasta. Repositório é essa pasta com histórico, publicada num site como o GitHub. Clonar é baixar uma cópia completa dela para o seu computador, pronta para usar e editar.

🎯 Objetivo: ter o kit numa pasta sua

No terminal, na pasta onde você guarda seus projetos (rode as duas linhas, uma de cada vez):

git clone https://github.com/inematds/inema-agent-runtime meu-projeto
cd meu-projeto
Como verificar: abra a pasta meu-projeto no gerenciador de arquivos. Dentro dela têm de estar a pasta runtime/ e os arquivos README.md, AGENTS.md e CLAUDE.md.

Como ler o desenho: a caixa cinza é a cópia pública, que você não altera. A caixa verde é a sua cópia: tudo o que o curso pede para editar fica nela. O cd do comando é o passo de "entrar" nessa caixa.

💡 Todo comando do curso roda daqui

Os caminhos das receitas começam em runtime/…. Eles só funcionam se o terminal estiver dentro da pasta do kit. Abriu um terminal novo? Entre de novo com cd meu-projeto.

3

Rode o diagnóstico

O doctor.mjs é o diagnóstico do kit. Ele confere quatro programas (Node, Claude Code, Codex e Ollama) e termina com uma palavra: PRONTO ou FALTA.

Ele só pergunta a versão de cada programa e se o Codex está logado. Não chama modelo nenhum, então não gasta cota. Pode rodar quantas vezes quiser.

🎯 Objetivo: saber o que está instalado e logado

No terminal, dentro da pasta do kit:

node runtime/scripts/doctor.mjs

Saída real (05/10/2026, Linux):

node    ok        24.13.0
claude  ok        2.1.289   login: abra `claude` uma vez; R2 usa ele
codex   ok        0.159.2   Logged in using ChatGPT
ollama  ok        0.33.2    opcional: modelos locais grátis

PRONTO: siga para runtime/receitas/R1-claude-usa-codex.md
Como verificar: a última linha começa com PRONTO. Se aparecer FALTA, veja o tópico 4. As versões na sua máquina podem ser outras; o que importa é a segunda coluna.

Como ler o desenho: as caixas azuis decidem o resultado; a cinza tracejada (Ollama) só informa. Basta um agente para dar PRONTO: o Claude Code sozinho já serve, o Codex sozinho também.

🆕 Novo aqui? "Saída 0" e "saída 1"

Todo comando, ao terminar, devolve um número para o sistema. Saída 0 quer dizer "deu certo"; qualquer outro número quer dizer "algo faltou". Você não vê esse número na tela, mas os agentes e os scripts do kit leem. É assim que o agente sabe, sem adivinhar, se o diagnóstico passou.

5

Veja como os dois agentes leem as mesmas regras

Cada agente procura, ao abrir, um arquivo de instruções com um nome diferente. O Codex lê o AGENTS.md. O Claude Code lê o CLAUDE.md.

O kit escreve as regras uma vez só, no AGENTS.md. O CLAUDE.md começa com @AGENTS.md, que manda o Claude incluir aquele arquivo. Resultado: uma regra, dois leitores.

Como ler o desenho: as duas setas azuis chegam na mesma caixa verde. Mudou uma regra no AGENTS.md? Os dois agentes passam a obedecer na próxima sessão. O settings.json fica de lado porque é coisa só do Claude Code.

📄 O CLAUDE.md inteiro (conteúdo real do kit)
@AGENTS.md

## Self-learning

Quando o humano corrigir você, ou você notar um erro seu: proponha a lição como uma linha na tabela "Aprendizado" de `runtime/POLITICA.md`. Depois de aprovada, ela entra em `## Lessons` do `AGENTS.md`.
Repare: a primeira linha puxa o AGENTS.md. O resto é a regra de aprender sem mudar as próprias regras, que você vê no módulo 4.2.

✓ O AGENTS.md manda o agente

  • ✓ Ler a POLITICA.md antes de agir
  • ✓ Só usar sistemas listados no CAPACIDADES.md
  • ✓ Usar o menor modelo que resolve (ROTEAMENTO.md)
  • ✓ Subir a escada de vias antes de dizer "impossível"

✗ O settings.json bloqueia no Claude Code

  • ✗ rm -rf
  • ✗ git push --force e git push -f
  • ✗ git reset --hard
  • ✗ servidor MCP fora da lista (só ponte-modelo está liberado)

💡 A guarda já vem ligada

O mesmo .claude/settings.json liga a guarda do kit: antes de editar um arquivo que outra sessão mexeu, ou de apagar arquivos, o Claude Code pergunta. Você não precisa configurar nada agora. Os detalhes estão no módulo 4.3.

6

Faça o primeiro pedido ao agente

Com o PRONTO na tela, abra o agente dentro da pasta do kit: digite claude (ou codex) e aperte Enter. Ele abre uma conversa no próprio terminal.

O primeiro pedido é o que o README sugere: o agente lê as regras do kit antes de fazer qualquer coisa e começa, com você, o mapa das suas ferramentas.

🆕 Novo aqui? Sessão interativa e pasta confiável

Sessão interativa é a conversa que abre quando você digita claude: você escreve, ele responde e age, até você sair. Pasta confiável é a pasta que você autorizou o Claude Code a usar. Na primeira vez ele pergunta se você confia na pasta: escolha "Yes, I trust this folder". Leia a opção marcada antes de apertar Enter; o CHANGELOG 0.2.0 do kit registra que, para as sessões em segundo plano (claude --bg), esse aviso abre com "No, exit" selecionado.

🎯 Objetivo: o agente ler as regras do kit e começar o mapa com você

Abra claude na pasta do kit e cole:

Leia runtime/LEIA-ME.md e me ajude a preencher o CAPACIDADES.md para o meu trabalho.
Como verificar: o agente mostra que abriu o runtime/LEIA-ME.md e começa a perguntar sobre os sistemas do seu trabalho. Se ele sair escrevendo no CAPACIDADES.md sem perguntar nada, pare e peça para ir sistema por sistema (módulo 1.4).
1

Ele lê as regras

O CLAUDE.md (e por ele o AGENTS.md) entra sozinho. O pedido acrescenta o LEIA-ME.md, com o ciclo e a escada.

2

Você conta o seu trabalho

A Clara falaria da planilha da agenda. A Sônia, do ERP que só exporta CSV. Diga os seus sistemas com as suas palavras.

3

Ainda não aceite nada

Por enquanto é conversa. Nos módulos 1.3 e 1.4 você aprende o que uma linha boa do mapa precisa ter antes de aprovar.

⚠️ Abra sempre na pasta do kit

Aberto em outra pasta, o agente não acha o CLAUDE.md, o AGENTS.md nem o .claude/settings.json. Ele funciona, mas sem as regras e sem os bloqueios do kit. Antes de digitar claude, confira se o terminal está dentro de meu-projeto.

Teste rápido (opcional): o doctor terminou com FALTA. Qual é o próximo passo?
