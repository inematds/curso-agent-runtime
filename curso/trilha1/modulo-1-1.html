Veja o que os vídeos de mods mostraram

Circularam vídeos mostrando "mods" do Claude Code. Num deles, o Claude passava a usar o uso do computador do aplicativo do Codex: clicava, digitava e lia a tela por meio de outra IA.

Em outro, várias sessões do Claude trabalhavam ao mesmo tempo, cada uma num papel, com um painel mostrando quem estava liderando e quem tinha travado. O apelido era "Threads".

Quase tudo foi feito por engenharia reversa: olhar o aplicativo rodando, descobrir por onde ele conversa por dentro e ligar um fio ali, sem convite do fabricante.

🆕 Novo aqui? Cinco palavras que aparecem o tempo todo

  • Claude Code — o Claude rodando no terminal da sua máquina. Ele lê e cria arquivos e roda comandos na pasta em que você o abre.
  • Codex — a ferramenta equivalente da OpenAI, também no terminal. O comando codex exec manda um pedido e recebe a resposta sem abrir a tela.
  • Agente — uma IA que recebeu ferramentas e age sozinha: cria arquivo, roda comando, abre site.
  • Mod (plugin) — um pacote que acrescenta coisas ao Claude Code: um painel, um comando novo, uma regra que roda antes de cada ação.
  • Engenharia reversa — descobrir como um programa funciona por dentro observando-o, sem documentação oficial.

Como ler o desenho: o trecho azul é a parte que o fabricante oferece (o app usando o computador). O trecho vermelho tracejado é o fio que alguém improvisou para entrar nele. É esse fio que some quando o app atualiza.

2

Separe descoberta de produto

A engenharia reversa tem valor. Ela prova que uma coisa é possível, mostra por onde o programa conversa e derruba o "não dá" dito cedo demais.

O problema começa quando o achado vira o sistema do dia a dia. Aí você passa a depender de algo que o fabricante pode mudar amanhã, sem aviso. A regra deste curso cabe numa linha: engenharia reversa é técnica de descoberta, não é produto.

✓ Como descoberta (serve)

  • ✓ Mostra que a ideia funciona antes de investir
  • ✓ Revela que dados o programa troca e por onde
  • ✓ Gera a pergunta certa: "existe uma via oficial para isso?"
  • ✓ Roda numa máquina de teste, com data anotada

✗ Como produto (não serve)

  • ✗ Quebra a cada atualização do aplicativo
  • ✗ Ninguém garante que o comportamento continua igual
  • ✗ Pode ferir os termos de uso do fornecedor
  • ✗ Você vira o único que sabe consertar

Como ler o desenho: a engenharia reversa entra só no primeiro quadro. O que decide o caminho é a caixa verde do meio. Na maioria dos casos de 2026, a resposta é "sim", e o seu sistema segue pela seta azul.

Quando alguém mostrar um truque impressionante, pergunte: "isso é o caminho ou é a prova de que existe um caminho?". Quase sempre é a segunda coisa.

🆕 Novo aqui? O que é "via oficial" e "CLI"

Via oficial é o caminho que o fabricante oferece para outros programas conversarem com o dele, e que ele se compromete a manter. CLI (interface de linha de comando) é um programa que você usa digitando comandos no terminal, como claude, codex ou git.

4

Entenda o que é o kit

O INEMA Agent Runtime é um kit que você copia para dentro do seu projeto. Ele faz o Claude Code e o Codex descobrirem, conectarem e usarem as ferramentas que você já tem, com regras claras do que podem fazer sozinhos.

Não é plataforma nem servidor. É uma pasta runtime/ com quatro arquivos de regras, scripts de diagnóstico e verificação, pontes, uma guarda e sete receitas testadas. Funciona pela assinatura do Claude Code e/ou do Codex.

🆕 Novo aqui? Assinatura não é API

A assinatura é o plano mensal que você já paga para usar o Claude ou o ChatGPT. Ela tem uma cota: um limite de uso por período. A API é outra conta, cobrada por uso, pensada para programadores. O kit roda só pela assinatura: nenhuma API paga é pré-requisito.

Percorra o ciclo de sete etapas

O arquivo runtime/LEIA-ME.md organiza tudo num ciclo: descobrir → conectar → rotear → executar → observar → verificar → aprender. Cada etapa tem um arquivo e uma pergunta.

E toda ação, em qualquer etapa, passa pela POLITICA.md: ela diz o que o agente faz sozinho e o que pede antes.

Como ler o desenho: o anel tracejado é a ordem das etapas, e o "aprender" (verde) devolve o ciclo para o começo com regras melhores. As linhas para o centro mostram que nenhuma etapa escapa da política.

O que olhar na tabela: as perguntas são as mesmas que você faria ao contratar alguém: o que existe, como chega, quem faz, como confere e o que melhora.

💡 O que é "prova" no kit

Toda receita termina com uma Prova: um comando e o texto que tem de aparecer. Exemplo da receita R1: rodar a ponte com "Responda apenas PONG" e ver PONG. Se não aparece, não funcionou, mesmo que o agente diga que sim.

Arquivo: runtime/exemplos/erp-vendas.csv

🆕 Novo aqui? ERP e CSV

ERP é o sistema de gestão da empresa (vendas, estoque, notas). CSV é uma planilha em texto puro: cada linha é um registro e as colunas são separadas por vírgula. Quase todo sistema antigo sabe "exportar CSV", e isso basta para o agente ler.

Como ler o desenho: cada degrau depende do anterior. Você só conecta (T2) o que descobriu (T1), só monta um time (T3) com pontes que funcionam, e só deixa o agente mais solto (T4) com política e registro de falhas.
