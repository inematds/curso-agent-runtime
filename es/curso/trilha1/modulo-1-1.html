Mira lo que mostraron los videos sobre mods

Circularon videos que mostraban "mods" de Claude Code. En uno de ellos, Claude empezaba a usar el uso de la computadora de la aplicación de Codex: hacía clic, escribía y leía la pantalla mediante otra IA.

En otra, varias sesiones de Claude trabajaban al mismo tiempo, cada una con un papel, y un panel mostraba quién lideraba y quién se había bloqueado. El apodo era "Threads".

Casi todo lo hizo ingeniería inversa: mirar la aplicación en funcionamiento, descubrir cómo se comunica internamente y conectar un cable ahí, sin invitación del fabricante.

🆕 ¿Eres nuevo aquí? Cinco palabras que aparecen todo el tiempo

  • Claude Code — Claude ejecutándose en la terminal de tu máquina. Lee y crea archivos y ejecuta comandos en la carpeta donde lo abres.
  • Codex — la herramienta equivalente de OpenAI, también en la terminal. El comando codex exec envía una solicitud y recibe la respuesta sin abrir la pantalla.
  • Agente — una IA a la que se le dieron herramientas y que actúa por su cuenta: crea archivos, ejecuta comandos, abre sitios.
  • Mod (plugin) — un paquete que añade funciones a Claude Code: un panel, un comando nuevo, una regla que se ejecuta antes de cada acción.
  • Ingeniería inversa — descubrir cómo funciona un programa por dentro observándolo, sin documentación oficial.

Cómo leer el diagrama: el tramo azul es la parte que ofrece el fabricante (la aplicación que usa la computadora). El tramo rojo punteado es el cable que alguien improvisó para entrar en ella. Ese cable desaparece cuando se actualiza la aplicación.

2

Separa el descubrimiento del producto

La ingeniería inversa tiene valor. Demuestra que algo es posible, muestra por dónde se comunica el programa y desmiente el "no se puede" dicho demasiado pronto.

El problema empieza cuando el hallazgo se convierte en el sistema de uso diario. Entonces pasas a depender de algo que el fabricante puede cambiar mañana sin avisar. La regla de este curso cabe en una línea: la ingeniería inversa es una técnica de descubrimiento, no un producto.

✓ Como descubrimiento (sirve)

  • ✓ Muestra que la idea funciona antes de invertir
  • ✓ Revela qué datos intercambia el programa y por dónde
  • ✓ Genera la pregunta correcta: "¿existe una vía oficial para esto?"
  • ✓ Se ejecuta en una máquina de prueba, con la fecha anotada

✗ Como producto (no sirve)

  • ✗ Se rompe con cada actualización de la aplicación
  • ✗ Nadie garantiza que el comportamiento siga igual
  • ✗ Puede infringir los términos de uso del proveedor
  • ✗ Te conviertes en la única persona que sabe arreglarlo

Cómo leer el diagrama: la ingeniería inversa entra solo en el primer recuadro. Lo que determina el camino es la caja verde del medio. En la mayoría de los casos de 2026, la respuesta es «sí» y tu sistema sigue por la flecha azul.

💡 Frase para guardar

Cuando alguien te muestre un truco impresionante, pregunta: "¿es el camino o es la prueba de que existe un camino?". Casi siempre es lo segundo.

🆕 ¿Eres nuevo aquí? Qué son «vía oficial» y «CLI»

Vía oficial es la vía que ofrece el fabricante para que otros programas se comuniquen con el suyo, y que se compromete a mantener. CLI (interfaz de línea de comandos) es un programa que usas escribiendo comandos en la terminal, como claude, codex o git.

4

Entiende qué es el kit

O INEMA Agent Runtime es un kit que copias dentro de tu proyecto. Hace que Claude Code y Codex descubran, conecten y usen las herramientas que ya tienes, con reglas claras sobre lo que pueden hacer por su cuenta.

No es una plataforma ni un servidor. Es una carpeta runtime/ con cuatro archivos de reglas, scripts de diagnóstico y verificación, puentes, una protección y siete recetas probadas. Funciona mediante suscripción de Claude Code y/o de Codex.

🆕 ¿Eres nuevo aquí? Una suscripción no es una API

A suscripción es el plan mensual que ya pagas para usar Claude o ChatGPT. Tiene una cuota: un límite de uso por período. La API es otra cuenta, que se cobra según el uso y está pensada para programadores. El kit funciona solo con la suscripción: no necesitas ninguna API de pago.

Recorre el ciclo de siete etapas

El archivo runtime/LEIA-ME.md organiza todo en un ciclo: descubrir → conectar → enrutar → ejecutar → observar → verificar → aprender. Cada etapa tiene un archivo y una pregunta.

Y toda acción, en cualquier etapa, pasa por la POLITICA.md: indica qué hace el agente por su cuenta y qué pide antes.

Cómo leer el diagrama: el anillo punteado indica el orden de las etapas, y «aprender» (en verde) devuelve el ciclo al inicio con mejores reglas. Las líneas hacia el centro muestran que ninguna etapa escapa a la política.

💡 Qué es una «prueba» en el kit

Toda receta termina con una Evidencia: un comando y el texto que debe aparecer. Ejemplo de la receta R1: ejecutar el puente con "Responda apenas PONG" y ver PONG. Si no aparece, no funcionó, aunque el agente diga que sí.

🧾

Sônia, 51 — contadora

Su cliente es una distribuidora cuyo ERP no tiene API: solo exporta un CSV de ventas. Sônia quiere el total por cliente sin tener que armar una hoja de cálculo a mano cada mes.

Archivo: runtime/exemplos/erp-vendas.csv

🆕 ¿Eres nuevo aquí? ERP y CSV

ERP es el sistema de gestión de la empresa (ventas, inventario, facturas). CSV es una hoja de cálculo en texto sin formato: cada línea es un registro y las columnas están separadas por comas. Casi todos los sistemas antiguos saben «exportar CSV», y eso basta para que el agente lo lea.

Cómo leer el diagrama: cada nivel depende del anterior. Solo conectas (T2) lo que descubriste (T1), solo formas un equipo (T3) con puentes que funcionan y solo das más libertad al agente (T4) con una política y un registro de fallos.
