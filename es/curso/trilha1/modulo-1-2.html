1

Verifica lo que necesitas tener

La lista es breve. El README del kit pide tres cosas: Node 18 o posterior, o Claude Code y/o Codex conectados con su propia suscripción, y una computadora con Linux o Mac. En Windows, usa WSL.

Basta con uno de los dos agentes para empezar. Con los dos, aprovechas todas las recetas, incluida la R1, en la que Claude le pide ayuda a Codex.

🆕 ¿Eres nuevo aquí? Cuatro términos de este módulo

  • Terminal — la ventana de texto donde escribes comandos y presionas Enter. En Mac, la aplicación se llama Terminal; en Linux, también.
  • Node — el programa que ejecuta los scripts del kit (los archivos .mjs). También incluye el npm, que instala herramientas.
  • WSL — Linux que se ejecuta dentro de Windows. Es la forma en que quienes usan Windows siguen este curso.
  • Inicio de sesión con la suscripción — iniciar sesión en Claude Code o Codex con la misma cuenta del plan mensual. Nada de claves de API.

✓ Lo necesitas

  • ✓ Node 18 o más nuevo
  • ✓ Claude Code o Codex (o ambos), con sesión iniciada
  • ✓ Linux, Mac o Windows con WSL
  • ✓ Una carpeta donde vivirá el kit

✗ No lo necesitas

  • ✗ Clave de API de pago
  • ✗ Servidor, nube o panel web
  • ✗ Saber programar
  • ✗ Ollama (es opcional: modelos locales gratis)

2

Clona el kit en tu máquina

El kit está en GitHub. Un comando copia todo a una carpeta nueva en tu computadora. El nombre meu-projeto es una sugerencia del README: si quieres, cámbialo por el nombre de tu trabajo.

La carpeta clonada se convierte en tu proyecto. Las reglas, los puentes y las recetas ya vienen en el lugar correcto. No instalas nada más.

🆕 ¿Eres nuevo aquí? Git, repositorio y clone

Git es el programa que guarda el historial de cambios de una carpeta. Repositorio es esta carpeta con historial, publicada en un sitio como GitHub. Clonar es descargar una copia completa en tu computadora, lista para usar y editar.

🎯 Objetivo: tener el kit en una carpeta propia

En la terminal, en la carpeta donde guardas tus proyectos (ejecuta las dos líneas, una a la vez):

git clone https://github.com/inematds/inema-agent-runtime meu-projeto
cd meu-projeto
Cómo verificar: abre la carpeta meu-projeto en el administrador de archivos. Dentro de ella debe estar la carpeta runtime/ y los archivos README.md, AGENTS.md e CLAUDE.md.

Cómo leer el diagrama: la caja gris es la copia pública, que no modificas. La caja verde es tu copia: todo lo que el curso te pide editar queda ahí. El cd del comando es el paso para "entrar" en esta caja.

💡 Todo comando del curso se ejecuta desde aquí

Las rutas de las recetas empiezan en runtime/…. Solo funcionan si la terminal está dentro de la carpeta del kit. ¿Abriste una terminal nueva? Vuelve a entrar con cd meu-projeto.

3

Ejecuta el diagnóstico

O doctor.mjs é o diagnóstico del kit. Revisa cuatro programas (Node, Claude Code, Codex y Ollama) y termina con una palabra: LISTO o FALTA.

Solo pregunta la versión de cada programa y si Codex tiene la sesión iniciada. No llama a ningún modelo, así que no consume cuota. Puedes ejecutarlo tantas veces como quieras.

🎯 Objetivo: saber qué está instalado y qué sesiones están iniciadas

En la terminal, dentro de la carpeta del kit:

node runtime/scripts/doctor.mjs

Salida real (05/10/2026, Linux):

node    ok        24.13.0
claude  ok        2.1.289   login: abra `claude` uma vez; R2 usa ele
codex   ok        0.159.2   Logged in using ChatGPT
ollama  ok        0.33.2    opcional: modelos locais grátis

PRONTO: siga para runtime/receitas/R1-claude-usa-codex.md
Cómo verificar: la última línea empieza con PRONTO. Si aparece FALTA, consulta el tema 4. Las versiones en tu máquina pueden ser otras; lo que importa es la segunda columna.

Cómo leer el diagrama: las cajas azules deciden el resultado; la gris discontinua (Ollama) solo informa. Basta con un agente para que quede LISTO: Claude Code por sí solo basta, Codex por sí solo también.

🆕 ¿Eres nuevo aquí? «Salida 0» y «salida 1»

Al terminar, todo comando devuelve un número al sistema. Salida 0 quiere decir "salió bien"; cualquier otro número quiere decir "faltó algo". No ves este número en pantalla, pero los agentes y los scripts del kit lo leen. Así es como el agente sabe, sin adivinar, si el diagnóstico pasó.

Lee cada línea del doctor

Cada línea tiene cuatro columnas: el programa, el estado, la versión y una nota. Cuando falta algo, la nota ya incluye el comando que lo resuelve. No tienes que adivinar.

💡 Hasta el doctor ya se equivocó y quedó registrado

La primera línea del runtime/FALHAS.md del kit cuenta un caso real: el doctor decía "codex sin login" aunque Codex tenía la sesión iniciada. La causa: Codex responde el estado de inicio de sesión por un canal que el script no leía. La corrección mínima fue leer ambos canales. Una línea, sin drama. Harás lo mismo en el módulo 4.2.

5

Mira cómo ambos agentes leen las mismas reglas

Al abrirse, cada agente busca un archivo de instrucciones con un nombre diferente. Codex lee el AGENTS.md. Claude Code lee el CLAUDE.md.

El kit escribe las reglas una sola vez, en el AGENTS.md. O CLAUDE.md empieza con @AGENTS.md, que le indica a Claude que incluya ese archivo. Resultado: una regla, dos lectores.

Cómo leer el diagrama: las dos flechas azules llegan a la misma caja verde. Cambió una regla en el AGENTS.md? Los dos agentes empiezan a obedecer en la próxima sesión. El settings.json queda al margen porque es algo exclusivo de Claude Code.

📄 El CLAUDE.md completo (contenido real del kit)
@AGENTS.md

## Autoaprendizaje

Cuando el humano te corrija o notes un error tuyo: propón la lección como una fila en la tabla «Aprendizaje» de `runtime/POLITICA.md`. Después de que la aprueben, se agrega a `## Lessons` de `AGENTS.md`.
Fíjate: la primera fila obtiene el AGENTS.md. El resto es la regla de aprender sin cambiar las propias reglas, que verás en el módulo 4.2.

✓ El AGENTS.md dirige al agente

  • ✓ Leer la POLITICA.md antes de actuar
  • ✓ Usar solo los sistemas enumerados en el CAPACIDADES.md
  • ✓ Usar el modelo más pequeño que resuelve el problema (ROTEAMENTO.md)
  • ✓ Recorrer las vías disponibles antes de decir «imposible»

✗ settings.json bloquea en Claude Code

  • ✗ rm -rf
  • ✗ git push --force e git push -f
  • ✗ git reset --hard
  • ✗ servidor MCP fuera de la lista (solo ponte-modelo está habilitado)

💡 La protección ya viene activada

Lo mismo .claude/settings.json activa la protección del kit: antes de editar un archivo que otra sesión modificó, o de borrar archivos, Claude Code pregunta. No tienes que configurar nada ahora. Los detalles están en el módulo 4.3.

6

Haz el primer pedido al agente

Con LISTO en pantalla, abre el agente dentro de la carpeta del kit: escribe claude (o codex) y presiona Enter. Se abre una conversación en la misma terminal.

El primer pedido es el que sugiere el README: el agente lee las reglas del kit antes de hacer cualquier cosa y empieza contigo a mapear tus herramientas.

🆕 ¿Eres nuevo aquí? Sesión interactiva y carpeta confiable

Sesión interactiva es la conversación que se abre cuando escribes claude: tú escribes, responde y actúa hasta que sales. Carpeta confiable es la carpeta que autorizaste a Claude Code a usar. La primera vez te pregunta si confías en la carpeta: elige «Yes, I trust this folder». Lee la opción marcada antes de presionar Enter; el CHANGELOG 0.2.0 del kit registra que, para las sesiones en segundo plano (claude --bg), este aviso se abre con «No, exit» seleccionado.

🎯 Objetivo: que el agente lea las reglas del kit y empiece el mapa contigo

Abre claude en la carpeta del kit y pega:

Lee runtime/LEIA-ME.md y ayúdame a completar CAPACIDADES.md para mi trabajo.
Cómo verificar: el agente muestra que abrió el runtime/LEIA-ME.md y empieza a preguntar sobre los sistemas de tu trabajo. Si se pone a escribir en el CAPACIDADES.md sin preguntar nada, detente y pide ir sistema por sistema (módulo 1.4).
1

Lee las reglas

O CLAUDE.md (y a través de él el AGENTS.md) se agrega automáticamente. La solicitud añade el LEIA-ME.md, con el ciclo y la escalera.

2

Tú cuentas tu trabajo

Clara hablaría de la hoja de cálculo de la agenda. Sonia, del ERP que solo exporta CSV. Describe tus sistemas con tus propias palabras.

3

Todavía no aceptes nada

Por ahora es una conversación. En los módulos 1.3 y 1.4 aprenderás qué debe incluir una buena línea del mapa antes de aprobarla.

⚠️ Abre siempre en la carpeta del kit

Abierto en otra carpeta, el agente no encuentra el CLAUDE.md, o AGENTS.md ni el .claude/settings.json. Funciona, pero sin las reglas ni los bloqueos del kit. Antes de escribir claude, comprueba si la terminal está dentro de meu-projeto.

Prueba rápida (opcional): el doctor terminó con FALTA. ¿Cuál es el siguiente paso?
