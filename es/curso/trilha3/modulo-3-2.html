MÓDULO 3.2

👥 Equipo de tres roles

Un modelo potente planifica, uno medio hace y uno ligero verifica. Cada rol usa solo el modelo que necesita, y la cuota rinde. Es la receta R2 del kit, con evidencia en el CHANGELOG.

1

Conoce al planificador, al ejecutor y al revisor

La receta R2 divide una tarea en tres roles. El planificador piensa y escribe el plan. El ejecutor haz. El revisor comprueba si realmente quedó listo.

Es el enrutamiento del módulo 3.1 aplicado a una sola tarea: pensar usa un modelo potente, hacer usa uno medio y verificar usa uno ligero. Nadie paga el nivel más alto para una tarea de verificación.

🆕 ¿Eres nuevo aquí? Subagente y rol

  • Subagente — un ayudante al que Claude Code llama durante la conversación. Recibe una parte del trabajo, la realiza con su modelo y sus herramientas y devuelve el resultado. Es una función oficial de Claude Code.
  • Papel — el «cargo» del subagente: qué hace, qué modelo usa y qué puede tocar. En el kit, cada rol es un archivo en .claude/agents/.

Qué revisar en la tabla: la columna Modelo baja de nivel desde la primera hasta la última fila (superior, ejecutor, más pequeño en el ROTEAMENTO.md). La tabla es la misma que en la receta R2.

Cómo leer el diagrama: la tarea avanza de izquierda a derecha. Solo el ejecutor (azul) modifica archivos. El revisor cierra con APROVADO; si algo falla, la línea roja discontinua devuelve al ejecutor la lista de cosas que debe corregir.

2

Lee los archivos de los roles

Cada rol es un archivo de texto breve. Arriba hay una ficha entre líneas ---; debajo, las instrucciones en portugués. Este es el .claude/agents/planejador.md, completo:

📄 .claude/agents/planejador.md (del kit)
---
name: planejador
description: Planeja uma tarefa antes de executar. Use no início do time de três papéis (runtime/receitas/R2). Não edita arquivos.
model: opus
tools: Read, Grep, Glob
---
Você é o planejador do time. Leia a tarefa e o que for preciso do projeto, sem alterar nada.

Devolva somente:
1. Plano em no máximo 5 passos.
2. Critérios de pronto, um por linha, no formato `comando → saída esperada`, que só passam se o trabalho for feito de verdade.
3. Riscos pela runtime/POLITICA.md (ações que exigem pedir antes).
Fíjate: la lista tools no tiene Write ni Edit. El planificador no puede alterar archivos, aunque quiera.

🆕 ¿Eres nuevo aquí? Frontmatter y herramientas

  • Frontmatter — la ficha en la parte superior del archivo, entre las dos líneas ---. Claude Code lee allí el nombre, la descripción, el modelo y las herramientas del rol.
  • description — le dice a Claude cuándo llamar a este rol. Por eso menciona la receta R2.
  • herramientas — las herramientas habilitadas: Read (leer), Grep/Glob (buscar), Write/Edit (crear y modificar), Bash (ejecutar comandos).
Papeltools: en el archivoInstrucción que mantiene el rol
planificadorRead, Grep, Glob"sin cambiar nada"
ejecutorRead, Write, Edit, Bash, Grep, Glob"no envíes, no borres, no gastes crédito; si el plan pide eso, detente y devuelve la pregunta"
revisorRead, Bash, Grep, Glob"No modifiques archivos." Termina con APROVADO o FALTA:

Qué revisar en la tabla: el revisor tiene Bash para ejecutar los criterios, pero no tiene Write ni Edit. Comprueba sin poder «corregir por debajo» lo que encontró.

  • ✓ Menciona la POLITICA.md
  • ✓ Cabe en una pantalla

3

Ejecuta el equipo desde la pantalla de Claude

La forma más sencilla es conversar. Abres Claude Code en la carpeta del kit y pides el equipo por los nombres de sus roles. Claude llama a cada subagente en orden.

La tarea de prueba es intencionalmente sencilla: crear un archivo con una frase. Así ves al equipo en acción sin preocuparte por el contenido.

🎯 Objetivo: ver los tres roles trabajando en una tarea pequeña

Abre claude en la carpeta del kit y pega (prompt de la receta R2):

Use o time: o planejador planeja, o executor faz e o revisor confere. Tarefa: crie saudacao.txt com a frase "Olá, comunidade INEMA".

Cuando termines, revisa el archivo en la terminal:

cat saudacao.txt

Resultado esperado (según la receta):

cat saudacao.txt muestra la frase y la respuesta termina con APROVADO.
Cómo verificar: el archivo tiene la frase «Hola, comunidad INEMA» y la última palabra del revisor es APROVADO. Si viene FALTA:, lee la lista: es lo que el ejecutor dejó de hacer.
1

El planificador devuelve el plan

Hasta 5 pasos, los criterios de finalización en el formato comando → saída esperada y los riesgos según la política.

2

El ejecutor lo hace y muestra la prueba

Crea el archivo, ejecuta el comando de prueba de cada paso y enumera lo que creaste o modificaste.

3

El revisor da el veredicto

Una línea por criterio, OK o FALLO con la salida, y al final APROVADO o FALTA:.

💡 El criterio se define antes del trabajo

El planificador escribe el criterio de finalización antes de que el ejecutor empiece. Así, el revisor comprueba el trabajo según lo acordado y no según lo que el ejecutor dice que hizo. Es la misma idea de «prueba» de las recetas.

4

Ejecuta el equipo sin abrir la pantalla

El mismo pedido cabe en una línea de terminal. No conversas: envías la tarea, esperas y lees la respuesta final. Sirve para repetir el trabajo del equipo cada semana con la misma frase.

🆕 ¿Eres nuevo aquí? El -p de Claude

claude -p "pedido" ejecuta la solicitud una vez e imprime la respuesta, sin abrir la pantalla de conversación. La «p» viene de captura de pantalla (imprimir). Es lo que permite llamar a Claude desde un script u otro agente.

🎯 Objetivo: ejecutar todo el equipo con un solo comando

En la terminal, dentro de la carpeta del kit:

claude -p "Use o time (planejador, executor, revisor). Tarefa: crie saudacao.txt com a frase 'Olá, comunidade INEMA'. Termine com a resposta do revisor."

Resultado comprobado en CHANGELOG 0.1.0:

modelos opus + sonnet + haiku usados; revisor APROVADO; saudacao.txt correto
Custo da R2 em cota: equivalente a ~US$ 0,73 de API (não é cobrança na assinatura).
Cómo verificar: la respuesta termina con la del revisor (APROVADO) e cat saudacao.txt muestra la frase.

Cómo leer el diagrama: a la izquierda, los tres roles quedan a la vista en la conversación. A la derecha, se ejecutan dentro de la caja morada de claude -p y solo ves lo que sale. Mismo equipo, misma cuota; cambia cuánto supervisas.

⚠️ -p no es lo mismo que segundo plano

O claude -p mantiene la terminal ocupada hasta que termine. Dejar que el equipo trabaje mientras haces otra cosa es el claude --bg, del módulo 3.3. Y no se mezclan: el CHANGELOG 0.2.0 registra que --bg no acepta -p.

5

Usa el equipo en tu trabajo

Para usarlo de verdad, cambia solo la tarea. La receta R2 trae dos ejemplos, uno para cada personaje del curso. Lo que cambia de uno a otro es lo que revisa el revisor.

🧾

Sônia — totales del ERP

Ejemplo de R2: «planifica y prepara un resumen del CSV exportado del ERP en export/; el revisor comprueba los totales".

Para practicar, usa el runtime/exemplos/erp-vendas.csv. Su total es R$ 856,00, una cuenta que puedes hacer a mano.

🩺

Clara — horarios disponibles

Ejemplo de R2: «lista los horarios libres de la semana en agenda.csv; el revisor comprueba que no aparezca ningún horario ocupado".

Para practicar, usa el runtime/exemplos/agenda.csv, con la Dra. Ana y el Dr. Bruno.

🎯 Objetivo: el equipo de Sonia, con un revisor que comprueba el total

Abre claude en la carpeta del kit y pega:

Use o time: o planejador planeja, o executor faz e o revisor confere. Tarefa: monte resumo-vendas.md com o total por cliente do runtime/exemplos/erp-vendas.csv e o total geral. O revisor confere os totais somando direto do CSV.

Para Clara, cambia la tarea:

Use o time: o planejador planeja, o executor faz e o revisor confere. Tarefa: liste em horarios-livres.md os horários livres da runtime/exemplos/agenda.csv. O revisor confere se nenhum horário ocupado apareceu.
Cómo verificar: el revisor termina con APROVADO. En el caso de Sônia, el total general debe dar R$ 856,00 (10×18,50 + 25×5,20 + 40×5,20 + 6×18,50 + 12×18,50). En el caso de Clara, compara con las líneas livre del CSV.

💡 Dile al revisor qué debe comprobar

"El revisor verifica" por sí solo es vago. "El revisor verifica los totales sumándolos directamente desde el CSV" se convierte en un criterio. Cuanto más concreto sea lo que verifica, más el APROVADO se aplica.

⚠️ El ejecutor se detiene antes de enviar o borrar

Según la política de R2, el ejecutor modifica archivos del proyecto (N3) y nada más. Si la tarea de Clara se convierte en "y envía la lista a los pacientes", se detiene y devuelve la pregunta: enviar tiene un límite N2 en la POLITICA.md.

6

Cambia los modelos y crea roles

Los roles son tuyos. La sección «Ajustes» de la R2 muestra las dos formas de hacer cambios: cambiar el modelo de un rol y crear un rol nuevo.

Para cambiar el modelo, edita la línea model: del archivo del rol. Los valores aceptados son haiku, sonnet, opus o inherit, que usa el mismo modelo de tu sesión.

📄 Frontmatter de .claude/agents/revisor.md (del kit)
---
name: revisor
description: Confere o trabalho do executor rodando os critérios de pronto do plano. Use no fim do time de três papéis (runtime/receitas/R2). Não edita arquivos.
model: haiku
tools: Read, Bash, Grep, Glob
---
Dónde hacer cambios: si el revisor deja pasar un error en las cuentas de Sônia, cámbialo model: haiku por model: sonnet. Es la regla «solo sube si falla» del módulo 3.1.
Valor de model:Nivel en ROTEAMENTO.mdCuando lo uses en el equipo
haikumenorverificar criterios simples
sonnetejecutor (o inferior)hacer el trabajo; revisor más atento
opusmáximo (o ejecutor, con poco esfuerzo)planificar
inheritel de tu sesióncuando ya hayas elegido el modelo al abrir el claude

Qué revisar en la tabla: la segunda columna vincula cada valor con la tabla del módulo 3.1. Ten en cuenta que sonnet aparece en dos niveles allí: el enrutamiento es una guía, no una prisión.

Para crear un papel, R2 indica copiar un archivo de .claude/agents/ y cambia el nombre, la descripción y las instrucciones. Puedes pedírselo al propio Claude, que muestra el cambio antes de guardarlo:

🎯 Objetivo: un cuarto rol, a partir del revisor

Abre claude en la carpeta del kit y pega:

Copia .claude/agents/revisor.md en .claude/agents/conferente-agenda.md. Cambia name, description e instrucciones: debe verificar si una lista de horarios disponibles coincide con las líneas libre de runtime/exemplos/agenda.csv. Mantén las mismas tools y model: haiku. Muestra el archivo antes de guardarlo.
Cómo verificar: el archivo nuevo existe en .claude/agents/, el frontmatter tiene name: conferente-agenda y la lista tools sigue sin Write e Edit.

Prueba rápida (opcional): ¿por qué el revisor del kit no tiene Write ni Edit?
