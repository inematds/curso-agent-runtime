La idea que atraviesa el curso

Ingeniería inversa no es un producto, es una técnica de descubrimiento.

Los videos sobre "mods" de Claude Code mostraron a Claude usando Codex y varias sesiones trabajando en paralelo, casi todo mediante ingeniería inversa. La idea es excelente; el método deja de funcionar con la siguiente actualización. Hoy casi todo eso tiene una vía oficial: codex exec, claude --bg e claude agents, plugins oficiales de Claude Code.

Regla del kit: sube la escalera y usa siempre la vía más estable que exista — API → MCP → CLI → SDK → uso de la computadora → puente local → ingeniería inversa (solo laboratorio).

Para quién es

🩺

Clara, 47 — dueña de una clínica

La agenda es una hoja de cálculo. Ella quiere que el agente indique los horarios disponibles de la Dra. Ana y el Dr. Bruno sin que nadie abra el archivo, y sin que el agente programe nada por su cuenta.

🧾

Sônia, 51 — contadora

El ERP del cliente no tiene API, solo exporta CSV. Ella quiere que se verifique el total de ventas por cliente, sin armar una hoja de cálculo a mano todos los meses.

Si ya usas un chat de IA, has oído hablar de Claude Code y Codex y quieres que trabajen con los sistemas de tu día a día, este curso es para ti. No necesitas ser programador: cada término técnico se explica la primera vez que aparece y cada comando incluye lo que deberías ver en pantalla.

🏁 Proyecto final: tu puente y tu equipo

Eliges un sistema de tu trabajo que no tiene API, completas el CAPACIDADES.md, elige la vía más alta posible, construye el puente, ejecuta un equipo de tres roles con la política "pregunta antes" y entrega la salida de verificar.mjs con todos los criterios OK, más una lección que tú mismo aprobaste.

El entregable es la carpeta runtime/ rellena, no es un video ni una presentación. Detalles en el módulo 4.4.
