🗺️ O mapa de capacidades

O runtime/CAPACIDADES.md é a lista do que o agente pode usar: uma linha por sistema, com via, nível, como chamar, política e data do teste. Sistema sem linha não é usado.

1

Leia as colunas do CAPACIDADES.md

No módulo 1.3 você descobriu a via de cada sistema. O mapa de capacidades é onde essa descoberta fica escrita, num formato que o agente lê antes de agir. O AGENTS.md manda: só use sistemas listados ali, pela via indicada.

Cada linha tem seis colunas. Cada coluna responde uma pergunta que você faria antes de deixar alguém usar o seu sistema.

Como ler o desenho: leia da esquerda para a direita como uma frase: "o sistema X, pela via Y, no degrau N, é chamado assim, com esta política, e foi testado nesta data". A caixa verde é a que mais pesa: sem ela, a linha não vale.

Entenda as duas linhas que já vêm prontas

O arquivo não chega vazio. Ele traz duas linhas já testadas: os próprios agentes. Um pode chamar o outro, e o mapa precisa dizer como.

Use estas duas como modelo de linha boa: via clara, nível da escada, comando exato, política e data.

📄 A tabela do runtime/CAPACIDADES.md (conteúdo real do kit)
| Sistema | Via | Nível | Como o agente chama | Política | Testado em |
|---|---|---|---|---|---|
| Codex CLI | CLI | 3 | `runtime/pontes/codex-exec.sh` | ler (N4) | 2026-10-05 ok |
| Claude Code | CLI | 3 | `claude -p --permission-mode plan` | ler (N4) | 2026-10-05 ok |
Repare: as duas estão no nível 3 (CLI), com política de leitura (N4) e data de teste. Nenhuma delas deixa o outro agente alterar arquivos por padrão.

🆕 Novo aqui? Ponte e modo de planejamento

Ponte é o que transforma uma via em algo que o agente chama. O codex-exec.sh é uma ponte: embrulha o codex exec com as regras do kit (módulo 2.1). Modo de planejamento (--permission-mode plan) é o jeito de rodar o Claude Code em que ele só lê e planeja, sem alterar nada. É por isso que a linha do Claude cabe em "ler".

Na linha do Codex, o Claude pede uma segunda opinião pela ponte; alterar arquivos pelo Codex é outra política, que você liga só quando pedir (receita R1). Na linha do Claude, ele é chamado sem abrir a tela, em modo de planejamento: lê e responde, sem mexer em nada.

✓ O que faz delas um bom modelo

  • ✓ Comando exato, que dá para copiar
  • ✓ Nível conferido na escada
  • ✓ Política só de leitura
  • ✓ Data com "ok" de um teste real

✗ O que uma linha ruim teria

  • ✗ "usar o Codex" sem dizer como
  • ✗ Nível chutado
  • ✗ Política "tudo liberado"
  • ✗ Nenhuma data

Use os exemplos para copiar

Abaixo da tabela, o arquivo traz uma seção "Exemplos para copiar": quatro linhas para casos comuns. Repare na última coluna de todas: pendente.

Pendente quer dizer que a linha descreve o plano, mas ninguém testou ainda na sua máquina. Começar de um exemplo parecido com o seu caso economiza metade do trabalho.

📄 Exemplos para copiar (conteúdo real do CAPACIDADES.md)

| ERP sem API                  | Exportação CSV diária   | 6 | ler ~/erp/export/*.csv          | ler (N4)        | pendente |

Como usar: copie a linha mais parecida para a tabela de cima, troque o nome e o caminho pelos seus, e deixe "pendente" até testar.

Preencha o mapa com o agente

O agente conhece a escada; você conhece o seu trabalho. Juntos, o mapa sai em minutos. O README traz o pedido pronto, o mesmo que você usou no módulo 1.2.

O LEIA-ME.md dá a dica de como conduzir: peça ao agente para preencher "comigo, nível por nível". É uma entrevista guiada, com você aprovando cada linha.

🎯 Objetivo: ter uma linha nova no CAPACIDADES.md para um sistema seu

Abra claude na pasta do kit e cole:

Leia runtime/LEIA-ME.md e me ajude a preencher o CAPACIDADES.md para o meu trabalho.

Se ele tentar fazer tudo de uma vez, complemente com:

Preencha comigo, nível por nível: um sistema por vez, uma pergunta por vez. Use os exemplos do CAPACIDADES.md como modelo e marque "pendente" em toda linha que ainda não testamos.
Como verificar: abra o runtime/CAPACIDADES.md. A linha nova tem as seis colunas preenchidas e, na última, "pendente" ou uma data com o resultado de um teste que você viu rodar.

Só deixe entrar linha testada

O arquivo abre e fecha com a mesma regra. No topo: "só entra linha com teste feito". No fim: "sistema sem linha aqui não é usado pelo agente".

Funciona como uma lista branca: o que não está na lista fica de fora. Isso impede o agente de inventar acesso a um sistema que ninguém conferiu.

Como ler o desenho: são duas portas em sequência. Só chega na caixa verde quem passa pelas duas. As caixas vermelhas não são erro: são o agente obedecendo a regra e devolvendo a decisão para você.

✓ Linha que pode entrar

  • ✓ Seis colunas preenchidas
  • ✓ Comando ou caminho exato em "como chama"
  • ✓ Política conferida na POLITICA.md
  • ✓ Data de um teste que você viu rodar

✗ Linha que fica de fora (ou pendente)

  • ✗ "Acho que tem API" sem teste
  • ✗ Comando que ninguém rodou
  • ✗ Política em branco
  • ✗ Data copiada de outra linha

⚠️ O agente não testa a si mesmo por palavra

Se o agente escrever "testado" na linha, peça para ver o comando e a saída. Data no mapa é de teste que aconteceu na tela, não de teste que ele "acha" que passaria. É a mesma ideia de prova das receitas: comando → saída esperada.

Olhe o software antes de dizer impossível

Antes de marcar um sistema como "sem via", observe o que o programa já oferece. Muita exportação mora num menu que ninguém abre. Muita integração está numa página de configurações esquecida.

Olhar é o lado bom da engenharia reversa: você descobre a via observando, sem ligar fio improvisado nenhum. E se depois de olhar não houver via, isso também vira registro.

1

Menus de exportar e relatórios

Procure "Exportar", "Salvar como", "Relatórios". Um CSV já é ponte local (degrau 6).

2

Configurações e integrações

Telas com "Integrações", "API", "Desenvolvedores" ou "Webhooks" apontam para os degraus 1 a 3.

3

Ajuda e site do fabricante

A documentação costuma listar o que o programa troca com outros. Mostre ao agente e peça para ele testar.

4

Não achou? Anote no LIMITES.md

O que você tentou, o que barrou e o contorno. Esse registro evita repetir a busca e mostra o que pedir ao fornecedor.

📄 As colunas do runtime/LIMITES.md (conteúdo real do kit)
| data | o que tentei | o que barrou | contorno | status |
|---|---|---|---|---|
Repare: o arquivo chega vazio. A primeira linha é sua. A POLITICA.md manda anotar aqui também todo experimento de engenharia reversa, que é só laboratório (módulo 4.4).
